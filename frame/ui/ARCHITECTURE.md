# frame/ui

The wall frame's dashboard: Rust (edition 2024), SDL3 straight on KMS. Target: RK3126, four
Cortex-A7, Mali-400 (Lima, GLES 2.0), 1 GB, 800×1280 portrait panel mounted upside down.

## Process and display

- `maison-ui.service`: `maison-frame-ui` on tty7 in a logind session (user `kiosk`, PAM
  `maison-ui`), no compositor. It turns its own picture (`MAISON_ROTATE=180`) and hides the
  cursor; the launcher (`/usr/local/sbin/maison-ui`) gives SDL the card that has the panel. The
  touch is already mapped by the device tree: never invert it.
- SDL 3 and SDL_ttf 3 built from source and linked in (8.9 MB armv7 binary; runtime deps libc,
  libm, libgcc_s). SDL's GLES 2 renderer, vsync on.
- Event-driven: the loop sleeps on SDL events (input, window, a user event posted by a worker
  thread). It wakes on its own only for time-based changes (a gesture going slow or late, each
  second of a timed one, a held slider value, a key held, a press's end, a value going stale,
  Maison gone, the minute of the clock and of time-based words, a toast, the page timeout, the
  dimming, the next photo) and during a fling or a photo's fade, paced by the present. A read identical to the last one draws
  nothing, nor does a Wi-Fi status identical to the last; a scroll or a press draws the last `Screen` again. Idle = no frame.

## Shared sources

| What | Source | Here |
|---|---|---|
| API types | `api/` (maison-api): screens, sun, Tempo (`Today::price_at`, the calendar), lamps, Meross (its days), Matter covers, scenes, remote, climate (the settings' tokens) and Nabaztag constants, `androidtv::SHORTCUTS`, every request body the frame sends (the backend's routes read the same structs), `Answer`, `OfDevice`, `DeviceRef`, `HOUSE_TZ` | path dependency, shared with the backend. Climate, Nabaztag, TV and Tuya answers are still read as JSON by field name |
| Paces | `maison_api::paces` | read directly; the web app's `paces.ts` is generated from the same table |
| Refusal codes | `maison_api::codes::Code` | words from the `code_<code>` keys, else from the status: a read's in its group, an order's in a toast |
| Photos | `maison_api::photos` (`GET /api/photos`, ids by content) | `src/photos/`: the list is a live source, what follows it runs off the drawing thread |
| Events | `maison_api::events` (`GET /api/events`) | one thread for the app's life; a `change` refreshes its prefix; pushed sources poll every `PUSHED_SAFETY_MS` while the stream is open; reconnect with backoff, immediately once paired |
| Wi-Fi | `frame/tools/src/wifi.rs`: the protocol with `maison-wifid`, what a name and a password may be | path dependency, shared with the root service |
| Paths | `src/paths.rs` | every API path, once |
| Words | `i18n/messages/*.json` | embedded; `k::KEY` consts generated by build.rs (message shapes checked); Intl-equivalent numbers, times, dates, durations, lists, plurals |
| Tokens | `web/src/styles/tokens.css` | build.rs: colours (both `light-dark()` sides), lengths, type scale, media-query values, the red-day hatch. Component measures not in tokens are in `ui/layout.rs`, each naming its Svelte origin |
| Icons | `web/src/lib/components/Icon.svelte` | build.rs: one typed const each; resvg rasterises once per size |
| Fonts | `web/static/fonts`, Fraunces from `web/node_modules` | build.rs (allsorts): WOFF2 → TTF, variable faces instanced per weight |
| Mark | `web/static/brand.svg` | header and door |

Pairing follows the web app (`/screens/pairing`, `/claim`, `POST /me` to renew; a screen with no
target says so, a paired one Maison cannot reach waits calmly). The cookie is
kept 0600 in `/android-data/maison/ui`, bound to its origin. Claims rotate over any, IPv4-only
and IPv6-only agents so the server records both of the screen's addresses. HTTPS only
(`MAISON_ALLOW_HTTP=1` for simulations); no proxy from the environment.

## Layout

```
src/main.rs      SDL, the loop, rotation, simulation shots, touch logging (MAISON_STATS=1)
config.rs        address (credential `target`, else MAISON_TARGET; none: it says so; MAISON_SETUP_SSID: the setup view, the
                 frame's own Wi-Fi from MAISON_SETUP_*), MAISON_WIFI_SOCKET, state dir, language, turn, scale
heartbeat.rs     MAISON_HEARTBEAT: a file touched once a frame was presented, then every 10 s
client.rs        ureq 3 + rustls; no redirects, no proxy, bounded waits; POST/PUT; per-family
                 IP agents; the event stream; failures: signed out, refused (Code), unreachable,
                 unreadable
paths.rs         API paths
live.rs          sources: one thread each at its pace while drawn, stale after STALE_CADENCES,
                 refresh(prefix), listen() for the event stream, `gone`: Maison silent, whatever
                 the source, until anything answers
pairing.rs       POST /me, codes, claims, expiry, removal (a read's 401 has /me asked again; only
                 its 401 forgets the cookie, Maison silent the screen waits)
commands.rs      gestures: optimistic target, slow, late, settle until re-read; one order in
                 flight per key, the latest waits; every failure said once (a toast: who, the
                 refusal's words; past its limit by itself); timed orders, a toggle's last order
backlight.rs     dims after DIM_AFTER (2 min): 25 % of the awake level by day, 4 % at night (sun
                 side, followed asleep), never off; the first touch only wakes, to 40 % at night
photos/          the family's photos while the panel sleeps: `sync` (a thread: the cache follows
                 the list, fetches one at a time, retries), `cache` (`<state>/photos/<id>.jpg`, 0700,
                 256 MiB at most, kept with Maison away, gone with a removed screen), `decode` (a
                 thread: zune-jpeg, one picture ahead at most), `show` (pure: order, the 60 s and
                 the 1 s fade, `Order`s for the GPU)
wifi.rs          the Wi-Fi's screens: one thread asks `maison-wifid` over its socket (never root, never wpa_cli), says only
                 what changed; opens by itself with no network or a lost one, leaves by itself; the list,
                 a password typed, joined, refused, tried again; what was typed goes after PAGE_IDLE
app.rs           screens and views (house, device pages, door), page timeout (PAGE_IDLE), touch:
                 the pressed target kept across redraws and shown at least PRESSED_MS, REACH
                 tolerance, jitter that scrolls nothing still taps, one finger followed, a slider
                 moved only sideways, a remote's key repeating while held, nothing reached under
                 the header, a toast, a dialog or what cannot act (`Target::Cover`)
families/        now, scenes, tempo, lamps (Hue + Zigbee), cats, climate, shutters, plugs,
                 nabaztag, tv (and the box): answers → groups and pages, pure, tested on backend
                 JSON
ui/              gfx, icon, model, layout (dashboard measures, measuring pass, column balance,
                 strip folding), bricks, screens, slider, touch, keyboard (the touch keyboard: AZERTY,
                 digits, symbols, shift, backspace, keys of 75 × 92 px, pure state, no timer of its own)
sim.rs           stdin driver for simulations (MAISON_STDIN=1)
```

Home layout = the web dashboard's `.dashboard`: groups in balanced columns ≥ 22rem (two on the
panel), each group one framed list of rows. Row padding is doubled vertically for touch. Group
heights come from the drawing code in a measuring pass (`P::measuring`). A row with a page is two
zones, the disc its on/off and the rest its page; a toggle's row without one is a toggle target
over its whole head. The header holds the time and the date, read across the room; a chip of
« Maintenant » scrolls to its group, « +N » shows them all.

What a wall screen may do, a person at home does: each device with more than its row has a page
(`View`): the air conditioner (mode, fan, vane, econo, sleep timer, each choice sent at once), the
TV and the box (pad, media keys, volume, the TV's input and Ambilight), a lamp (its white, a Zigbee
lamp's colors and effects), a plug (volts, amps, its days, the month's estimate), a cat device
(its local connection, what it reports, its gestures), Tempo (calendar, forecast, prices, the
forecast's reliability). What cannot be undone (the fountain's counters, the litter's level) is
asked first in a dialog (`Act::Ask`): a wall is touched by anyone.

Maison silent, one band along the bottom says so for the whole house: no line per group, no gesture
reachable (`Over::gone`), everything back by itself at the first answer.

Nobody at the frame for `DIM_AFTER`, its photos take the panel (`Screen::Photos`): random order, each
photo once before any comes again, 5 s each, a 1 s crossfade of two textures (the first one over
the ground), scaled to cover, the time small in a corner. The backlight goes on by day and night as
it does. Paired or waiting for Maison, never at a door; with none kept, the house only dims. No band,
toast or dialog over them, nothing to reach: the first finger only brings the house back. Between
two fades only the clock's minute draws, and no house source is read.

The Wi-Fi's screens (`Screen::Wifi`, `Screen::Password`) come over whoever the frame is, without a
network nothing behind them can be reached; only the photos come first, and the first finger finds
them again. No band, no way back while the frame has no network. Maison's address is never typed:
`/android-data/maison/target` over SSH, else the image's. Each door offers « Réseau Wi-Fi », and so
does the band of Maison's silence; a house that answers offers nothing. With the frame its own Wi-Fi
(the power key held) the setup view stays alone.

Not on the frame: settings (night hours, preferences, meal plans, a shutter's schedule, a plug's
LED), pairing, sideloading, admin, the keymap: what the backend refuses a screen
(`not_for_screens`) stays out.
