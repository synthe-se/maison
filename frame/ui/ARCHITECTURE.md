# frame/ui

The wall frame's dashboard: Rust (edition 2024), SDL3 under cage on KMS. Target: RK3126, four
Cortex-A7, Mali-400 (Lima, GLES 2.0), 1 GB, 800×1280 portrait panel mounted upside down.

## Process and display

- `maison-ui.service`: cage on tty7 in a logind session (user `kiosk`, PAM `maison-ui`), one
  client, `maison-frame-ui`. The launcher (`/usr/local/sbin/maison-ui`) turns the output 180°
  with `wlr-randr`; if refused, the app turns its own picture (`MAISON_ROTATE=180`). The touch
  is already mapped by the device tree: never invert it.
- SDL 3 and SDL_ttf 3 built from source and linked in (8.9 MB armv7 binary; runtime deps libc,
  libm, libgcc_s). SDL's GLES 2 renderer, vsync on.
- Event-driven: the loop sleeps on SDL events (input, window, a user event posted by a worker
  thread). It wakes on its own only for time-based changes (a gesture going slow or late, a held
  slider value, a value going stale, a toast, the page timeout, the dimming) and every frame
  during a fling. Idle = no frame.

## Shared sources

| What | Source | Here |
|---|---|---|
| API types | `api/` (maison-api): screens, sun, Tempo (`Today::price_at`), lamps, Meross, Matter covers, scenes, remote, climate and Nabaztag constants, `androidtv::SHORTCUTS`, request bodies, `Answer`, `DeviceRef`, `HOUSE_TZ` | path dependency, shared with the backend. Climate, Nabaztag, TV and Tuya answers are still read as JSON by field name |
| Paces | `maison_api::paces` | read directly; the web app's `paces.ts` is generated from the same table |
| Refusal codes | `maison_api::codes::Code` | words from the `code_<code>` keys, else from the status |
| Events | `maison_api::events` (`GET /api/events`) | one thread for the app's life; a `change` refreshes its prefix; pushed sources poll every `PUSHED_SAFETY_MS` while the stream is open; reconnect with backoff, immediately once paired |
| Paths | `src/paths.rs` | every API path, once |
| Words | `i18n/messages/*.json` | embedded; `k::KEY` consts generated by build.rs (message shapes checked); Intl-equivalent numbers, times, dates, durations, lists, plurals |
| Tokens | `web/src/styles/tokens.css` | build.rs: colours (both `light-dark()` sides), lengths, type scale, media-query values, the red-day hatch. Component measures not in tokens are in `ui/layout.rs`, each naming its Svelte origin |
| Icons | `web/src/lib/components/Icon.svelte` | build.rs: one typed const each; resvg rasterises once per size |
| Fonts | `web/static/fonts`, Fraunces from `web/node_modules` | build.rs (allsorts): WOFF2 → TTF, variable faces instanced per weight; Noto Sans fallback |
| Mark | `web/static/brand.svg` | header and door |

Pairing follows the web app (`/screens/pairing`, `/claim`, `POST /me` to renew). The cookie is
kept 0600 in `/android-data/maison/ui`, bound to its origin. Claims rotate over any, IPv4-only
and IPv6-only agents so the server records both of the screen's addresses. HTTPS only
(`MAISON_ALLOW_HTTP=1` for simulations); no proxy from the environment.

## Layout

```
src/main.rs      SDL, the loop, rotation, simulation shots, touch logging (MAISON_STATS=1)
config.rs        address (credential `target`, else MAISON_TARGET), state dir, language, turn, scale
client.rs        ureq 3 + rustls; no redirects, no proxy, bounded waits; POST/PUT; per-family
                 IP agents; the event stream; failures: signed out, refused (Code), unreachable,
                 unreadable
paths.rs         API paths
live.rs          sources: one thread each at its pace while drawn, stale after STALE_CADENCES,
                 refresh(prefix), listen() for the event stream
pairing.rs       POST /me, codes, claims, expiry, removal
commands.rs      gestures: optimistic target, slow, late, settle until re-read; one order in
                 flight per key, the latest waits
backlight.rs     dims after DIM_AFTER (2 min): 25 % of the start level by day, 4 % at night (sun
                 side), never off; the first touch only wakes
app.rs           screens and views (house, Tempo page, door), page timeout (PAGE_IDLE), touch:
                 the pressed target kept across redraws, REACH tolerance, jitter that scrolls
                 nothing still taps
families/        now, scenes, tempo, lamps (Hue + Zigbee), cats, climate, shutters, plugs,
                 nabaztag, tv: answers → groups, pure, tested on backend JSON
ui/              gfx, icon, model, layout (dashboard measures, measuring pass, column balance,
                 strip folding), bricks, screens, slider, touch
sim.rs           stdin driver for simulations (MAISON_STDIN=1)
simulate.sh sim/ the armv7 binary on the frame's userland under qemu
```

Home layout = the web dashboard's `.dashboard`: groups in balanced columns ≥ 22rem (two on the
panel), each group one framed list of rows. Row padding is doubled vertically for touch. Group
heights come from the drawing code in a measuring pass (`P::measuring`). A row whose lead is a
toggle is a toggle target over its whole head.

Not on the frame: device pages, settings, admin, the keymap.

## Tests

- `cargo fmt`, `cargo clippy --all-targets -D warnings`, `cargo deny check` (no GPL), unit tests:
  client against a stub server, pairing, live, commands, sliders, touch, backlight, words,
  tokens, fonts, icons, every family on backend JSON, layout (balance, fold, hits), a real
  drawing on SDL's dummy driver.
- `e2e/frame.ts` (in `bun run all`): real backend, simulated house behind a proxy, paired from a
  browser, then driven (lamp, slider, AC, plug, shutter, Tempo page, a lamp that never answers,
  removal); checks the event stream opens once at pairing and stays open. Shots in `e2e/shots`.
- `FRAME_SIM=armv7`: the same scenario on the armv7 binary in Debian trixie armhf under qemu,
  headless cage, llvmpipe.
